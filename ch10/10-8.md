# 10.8 非同期エフェクトの追加

当初の設計では、非同期エフェクトも使用していたことを思い出す（p.129 再掲）。

```fs
// タイプ数を減らすためだけのalias
type AsyncResult<'success, 'failure> = Async<Result<'success, 'failure>>

// アドレスの存在チェック関数の型定義
type CheckAddressExists =
  UnvalidatedAddress -> AsyncResult<CheckedAddress, AddressValidationError>
```

エラーエフェクトと同様に、非同期エフェクトも asyncResult コンピュテーション式を定義することで扱いやすくなる。
型を AsyncResult に統一しなければいけないので注意（以前、AsyncやResultを1つでも使うと汚染していくという話があったのはそういうこと）。

```fs
let validateOrder : ValidateOrder =
  fun checkProductCodeExists checkAddressExists unvalidatedOrder ->
    asyncResult {  // --> 補足1.
      let! orderId =
        unvalidatedOrder.OrderId
        |> OrderId.create
        |> Result.mapError ValidationError
        |> AsyncResult.ofResult  // --> 補足2.
      let! customerInfo =
        unvalidatedOrder.CustomerInfo
        |> toCustomerInfo
        |> AsyncResult.ofResult
      let! checkedShippingAddress = // チェック済みの住所を取り出す
        unvalidatedOrder.ShippingAddress
        |> toCheckedAddress checkAddressExists  // --> 補足3.
      let! shippingAddress = // チェック済み住所の処理
        checkedShippingAddress
        |> toAddress
        |> AsyncResult.ofResult
      let! billingAddress = ...
      let! lines = ...
      let validatedOrder : ValidatedOrder = {
        OrderId = orderId
        CustomerInfo = customerInfo
        ShippingAddress = shippingAddress
        BillingAddress = billingAddress
        Lines = lines
      }
      return validatedOrder
    }
```

補足1. asyncResult式を使うことで、bindを明示的に書かなくてもつないでいけるようになる。

```fs
// 以下のコードは
asyncResult {
  let! orderId =
    unvalidatedOrder.OrderId
    |> OrderId.create
    |> ...
  let! customerInfo =
    unvalidatedOrder.CustomerInfo
    |> ...
  ...
  return validatedOrder
}

// 以下のコードと等価…と理解
asyncResult.Bind( (unvalidatedOrder.OrderId |> OrderId.create |> ...), fun orderId ->
  asyncResult.Bind( (unvalidatedOrder.CustomerInfo |> ...), fun customerInfo ->
    ...
        asyncResult.Return(validatedOrder)
  )
)
```

補足2. OrderId.createなどの結果をAsyncResultに合わせる必要がある。

```fs
let! orderId =
  unvalidatedOrder.OrderId
  |> OrderId.create
  |> Result.mapError ValidationError
  |> AsyncResult.ofResult // ResultをAsyncResultに持ち上げる

// @see https://github.com/swlaschin/DomainModelingMadeFunctional/blob/8153616b1dc0d5a0bb9e965cbe14a46b0dd4f3cf/src/OrderTakingEvolved/Result.fs#L391-L394
module AsyncResult =
    ...
    let ofResult x : AsyncResult<_,_> =
        x |> Async.retn

module Async =
    ...
    let retn x =
        async.Return x
```

補足3. CheckAddressExists のエラー型は AddressValidationError で、ValidationError 型と互換性がないため、エラー型を合わせてやる必要がある。

```fs
let! checkedShippingAddress = // チェック済みの住所を取り出す
  unvalidatedOrder.ShippingAddress
  |> toCheckedAddress checkAddressExists

let toCheckedAddress (checkAddress:CheckAddressExists) address =
  address
  |> checkAddress
  |> AsyncResult.mapError (fun addrError ->
    match addrError with
    | AddressNotFound -> ValidationError "Address not found"
    | InvalidFormat -> ValidationError "Address has bad format"
    )

// @see https://github.com/swlaschin/DomainModelingMadeFunctional/blob/8153616b1dc0d5a0bb9e965cbe14a46b0dd4f3cf/src/OrderTakingEvolved/Result.fs#L312-L314
module AsyncResult =
    ...
    let mapError f (x:AsyncResult<_,_>) : AsyncResult<_,_> =
        Async.map (Result.mapError f) x

module Async =
    ...
    let map f xA =
        async {
        let! x = xA
        return f x
        }
```
